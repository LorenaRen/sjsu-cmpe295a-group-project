# mrs_telemetry (Module 7)

Records every episode into one self-describing run folder, and checks the folder afterwards.

```
results/<experiment>/<run_id>/
  run.json            what ran: git commit (and uncommitted changes), host, world, robots, planner, recording settings
  bag/                MCAP bag (rosbag2): every canonical topic + /clock, /tf, /tf_static, /rosout, in sim time
  gz_log/             Gazebo state log (state.tlog + meshes), for visual replay
  events.jsonl        one line per decision: mission, dialogue turns, plans, verdicts, task status, events
  llm_log.sqlite      every LLM request/response and one row per planning cycle (Module 4)
  qos_overrides.yaml  how the recorder subscribed to latched topics
  ros_log/            every node's ROS log files (the same lines are in the bag, on /rosout)
  sim/                robot SDFs and bridge.yaml generated by sim.launch.py
  check.json          check_run's report and the run's outcome
  results.json        episode metrics (Module 11, later)
```

## Run

```bash
colcon build --packages-up-to mrs_telemetry     # builds the sim, gate and planner too
source install/setup.zsh

# a whole recorded episode: sim + gate + planner + recorder, the mission sent for you; it ends by itself
# once the robots get a plan (replans included), 600 s at most
ros2 launch mrs_telemetry episode.launch.py \
    mission:="robot_a: go to room_e. robot_b: go to room_w." duration:=600
ros2 launch mrs_telemetry episode.launch.py fake_script:=narrow_aisle mission:="..."   # no LLM

# or only the recorder, next to launches you start yourself
ros2 launch mrs_telemetry record.launch.py run_dir:=results/dev/try1

# afterwards
ros2 run mrs_telemetry check_run results/dev/<run_id>
ros2 bag info results/dev/<run_id>/bag
gz sim -s -r --playback results/dev/<run_id>/gz_log       # replay the Gazebo log: the server...
gz sim -g                                                 # ...and the GUI in a second terminal (macOS needs both)
```

With a mission, the episode **ends by itself** when the planning cycle is over: the robots got a plan
(APPROVE, or FALLBACK when none was approved; replans in between are waited for), plus `end_grace_s`
(5 s). `end_on_plan:=false` keeps it running; `duration` is a hard limit. Otherwise stop with **Ctrl-C**. Every process then gets SIGINT: the recorder closes
the bag and writes `metadata.yaml`, Gazebo closes its log, the telemetry node writes `telemetry_end`.
A recorder killed with SIGKILL leaves a bag without `metadata.yaml`; `ros2 bag reindex <run_dir>/bag`
rebuilds it.

## Pieces

| Piece | What it does |
|---|---|
| `topics.py` | The record list from `mrs_common.names` (every canonical topic for the fleet + `/clock`, `/tf`, `/tf_static`), QoS overrides for latched topics, the `ros2 bag record` command, which topics a run must have. |
| `run_folder.py` | Folder names, `run.json` built up section by section (`git`, `recording`, `episode`, `sim`, `planner`; Module 9 will add its own), git commit and dirty state. |
| `events.py` | One event per decision message, and per coordinator log line that is a decision (`replan` steps, `cycle_done`); the `events.jsonl` writer (flushed per line), safety-override throttle. |
| `telemetry_node.py` | `ros2 run mrs_telemetry telemetry`: subscribes to the decision topics and `/rosout`, writes `events.jsonl`. |
| `send_mission.py` | `ros2 run mrs_telemetry send_mission`: publishes a mission once, after the coordinator and the recorders have subscribed; with `wait_for_plan` it then waits for the robots' plan and exits, which ends the episode. |
| `episode_end.py` | When the episode is over: the first ValidatedPlan after the mission, plus a grace period. |
| `check_run.py` | `ros2 run mrs_telemetry check_run <run_dir>`: checks run.json, the bag (from its metadata.yaml), events, Gazebo log, LLM log. Pure Python, `--json` for scripts. |
| `launch/record.launch.py` | The recorder and the telemetry node for one run folder. |
| `launch/episode.launch.py` | Sim (with `record_gz_log`), gate, planner (`log_file` in the run folder) and recorder, plus optional mission and duration. |

## Notes

- **Sim time.** The bag (`--use-sim-time`) and `events.jsonl` (`t`) are stamped with Gazebo's clock,
  so the bag, the events and the Gazebo log share one timeline. Nothing reaches the bag before the
  first `/clock`; use `sim_time:=false` on `record.launch.py` when no Gazebo runs.
- **Missing topics are normal for now.** World state (Module 3), the executor and CBF filter (Module 6)
  and markers (Module 8) do not publish yet. Their topics are on the record list (so nothing changes
  when they arrive), but rosbag2 leaves a topic out of the bag until a node publishes it; `check_run`
  lists them by who would publish them, as warnings, not errors.
- **One episode id.** `episode.launch.py` gives the planner the run's episode id
  (`<experiment>_<run_id>`), so the run folder, every message and the LLM log share it.
- **Outcome.** `check_run` reads `events.jsonl` and says how the run ended: approved or fallback (with
  the cause), how many plans went to the gate, how many replans started and failed (a failed replan
  sends nothing to the gate; its trace is the coordinator's log line, recorded as a `replan` event;
  a replan whose plan the goal check refused, `mission_mismatch "replanned plan: ..."`, counts too;
  and how many replans needed a repair call),
  the mean replan time, and the sim time from the mission to the robots' plan.
- **Run folder names** default to the date and time plus 4 random hex digits
  (`20261126-110535-3f2a`), so parallel runs never collide; Module 9 should pass its own `run_id`. It saves the report as `check.json` in the run folder (`--no-write`
  to skip).
- **`duration` includes Gazebo's start-up** (about 20–25 s on a Mac): it is a hard limit, not the
  episode's length.
- **Cameras are off** in recordings by default (`camera:=false`): images dominate the bag size.
- **The events and the bag should agree.** `check_run` compares the number of each decision in
  `events.jsonl` with the bag's message count on that topic.

Tests: `python -m pytest` in this folder (no ROS needed for most); the node and launch-helper tests
need the built and sourced workspace and skip otherwise.
